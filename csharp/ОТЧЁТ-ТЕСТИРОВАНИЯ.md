## Итог

Основные функции приложения работоспособны. BLE-лента найдена, проверка связи успешна, тестовый оранжевый цвет отправлен. Ambilight использует DXGI, режим вспышек отправляет цвета, ручные красный/зеленый/синий применяются. Настройки Ambilight `20–70%` и автозапуск подсветки сохраняются и восстанавливаются после перезапуска приложения. После нового запуска BLE-лента подключилась автоматически.

Полный перезапуск Windows-службы выполнить из текущего неадминистративного сеанса не удалось: ОС вернула `Access denied / Cannot open service`. Служба при этом продолжала отвечать. Поставляемый `ПЕРЕЗАПУСК.bat` перезапускает только `OpenTuyaSync.exe`, а не службу, поэтому он не эквивалентен перезагрузке службы.

## Ошибки и задержки

1. **Высокий приоритет — найденные BLE-устройства имеют некорректную подпись.** В выпадающем списке отображается `OpenTuyaSync.Core.Ipc.DiscoveredDevice` вместо имени и MAC. Само устройство выбирается и его корректный MAC подставляется в редактор.
2. **Средний приоритет — первый запуск был аномально медленным.** Две попытки запуска через штатный механизм управления окном завершились тайм-аутом по ~15 с без процесса; прямой запуск достиг InputIdle примерно за 16,6 с. Последующий перезапуск UI занял около 1 с.
3. **Средний приоритет — масштаб яркости устройства не сохранился.** В UI значение было изменено со 100% на 80%, нажаты «Сохранить устройство» и «Сохранить все настройки», но в `config.json` осталось `brightness_scale: 1`. Пределы Ambilight и `auto_start_capture` сохранились корректно.
4. **Средний приоритет — сценарий `ПЕРЕЗАПУСК.bat` не перезапускает службу.** Он завершает только `OpenTuyaSync.exe`, ждет 2 секунды и запускает UI заново. Название и документация могут создавать впечатление имитации полной перезагрузки.
5. **Инфраструктурное ограничение — служба требует повышения прав для остановки.** `Restart-Service OpenTuyaSync` вернул `Cannot open ... service`; состояние осталось `Running`. Проверка полного stop/start службы не выполнена.
6. **Низкий приоритет — статус службы постоянно показывает 0 устройств.** В разделе службы видно `Устройств подключено: 0`, журнал печатает пустое `Устройства на службе:`, хотя BLE-статус приложения показывает 1. Для BLE это соответствует архитектуре (BLE обслуживает UI), но сообщение без пояснения выглядит как ошибка.
7. **Низкий приоритет — при переключении источника статус BLE временно остается `подключение...` до 10–11 с**, хотя счетчик отправок уже растет. После завершения статус становится `Bluetooth: 1`.
8. **Низкий приоритет — закрытие крестиком сворачивает приложение в трей.** При повторном запуске можно временно получить второй процесс/окно. Для гарантированного рестарта пришлось завершить оба UI-процесса и запустить один экземпляр.

## Проверка устойчивости

- Выполнены повторные переходы между тремя вкладками; зависаний и падений нет.
- Выполнены запуск, остановка и повторный запуск Ambilight; состояние восстановилось.
- Выполнено последовательное переключение экран → вспышки → музыка → ручное управление.
- Команды ручного применения трех основных цветов приняты UI; их фактическое визуальное выполнение уточнено в дополнении ниже.
- После принудительного завершения UI-процессов и запуска нового экземпляра конфигурация загрузилась, захват DXGI и BLE подключение восстановились автоматически.
- `agent_crash.log` не создан; процесс оставался `Responding=True`.

## Рекомендации

1. Добавить человекочитаемое представление `DiscoveredDevice` (`Name · MAC`) в BLE-списке.
2. Исправить сохранение `brightness_scale` после «Сохранить устройство».
3. Явно подписать в UI, что счетчик устройств службы не включает BLE, либо показывать раздельные счетчики.
4. Переименовать `ПЕРЕЗАПУСК.bat` в «перезапуск приложения» или добавить отдельный повышенный сценарий для stop/start службы.
5. Предотвращать параллельные UI-процессы или при повторном запуске надежно активировать существующее окно.
6. Синхронизировать статус BLE с фактической готовностью передачи, чтобы `подключение...` не сохранялось при уже растущем счетчике кадров.

## Дополнение: визуальная проверка ручной смены цвета по веб-камере

Дата и время: 15.10.2026, 18:30–18:33 (Europe/Kiev).  
Источник визуальной проверки: live-preview Iriun Webcam v2.9.9. В кадре видна подсветка за монитором; исходно и на всех контрольных снимках она синяя.

|---|---:|---:|---|---|
| RGB `255,0,0`, «Применить цвет» | 323 мс | 14,2 с | Подсветка осталась синей | Не пройдено |
| RGB `0,255,0`, «Применить цвет» | 426 мс | 7,7 с | Подсветка осталась синей | Не пройдено |
| RGB `0,0,255`, «Применить цвет» | 468 мс | 7,7 с | Синяя подсветка видна; это совпадает с исходным состоянием, поэтому сама команда не доказывает передачу | Не подтверждено |
| «Включить» | 3141 мс | затем повторен красный тест | Подтверждения подключения/смены нет | Не пройдено |
| RGB `255,0,0`, «Применить цвет» после «Включить» | 211 мс | 9,3 с | Подсветка осталась синей | Не пройдено |
| «Выключить» | 3129 мс | 11,3 с | Подсветка осталась синей, не погасла | Не пройдено |

Во всех случаях приложение принимало действия: RGB-ползунки и блок предпросмотра менялись на ожидаемые значения. Журнал UI фиксирует `Отправлен цвет: Rgb(...)`, `Лента включена.` и `Лента выключена.`, то есть команда прошла как минимум до уровня журналирования приложения. Однако после ручного применения строка состояния показывала `Подсветка: остановлена`, `Bluetooth: —`, `Отправлено: 0`, а фактическая лента на веб-камере не изменилась. Данные веб-камеры позволяют заключить, что ручные команды не были доставлены или не были применены фактической BLE-лентой.

Добавлен дефект высокого приоритета: **ручные команды ELK-BLEDOB не оказывают наблюдаемого физического эффекта.** Воспроизводится для красного, зеленого, включения и выключения; выдержка ожидания после команд составляла до 14,2 с. Необходимо диагностировать путь `Вручную` → локальный BLE-провайдер: создание/сохранение соединения, отправку команды, коды возврата и отображение статуса ошибки. Для сравнения, в автоматическом Ambilight ранее фиксировалось `Bluetooth: 1` и рост счетчика кадров, а проверка связи сообщала «подключено 1 из 1» и тестовый оранжевый цвет.
